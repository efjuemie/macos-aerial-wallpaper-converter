# v1.0.0 分离模式可行性记录（P0）

日期：2026-10-11。审查基线：`09a178e41cf3b336f7730899c93b389343caf689`，本地与 GitHub main 一致，应用为 v0.8.5 / build 13。

## 结论与阶段关卡

**P0 未通过，暂不能发布 v1.0.0 完整分离功能。** 当前实测的原生设置路径只能建立独立屏保 A 与桌面 B，未实现真实锁屏动态 A 与桌面静态 B。这不是所有 macOS 版本或所有可能实现均不支持的证明；目前没有可加入兼容白名单的系统组合。

| 阶段 | 状态 | 原因 |
| --- | --- | --- |
| P0：审计、原生行为、配置差分 | 已完成本轮审计与两次实际锁屏对照；关卡失败 | 自定义 A 与 Apple 视频 A 对照均未满足实际锁屏播放 A |
| P1：模式模型、注入服务、事务基础 | 未开始 | 必须等待 P0 通过 |
| P2：已验证系统后端与完整恢复 | 未开始 | 没有已验证的分离后端或系统白名单 |
| P3：平行互斥模式与原生 UI | 未开始 | 不提供看似可用但无法生效的分离入口 |
| P4：完整矩阵、版本升级、发行 | 阻断 | 不创建 v1.0.0 标签、DMG 或正式分离发布 |

任务书原要求专门测试账户/测试机。用户在本次对话明确授权直接使用当前真机，并确认可以现场观察；本轮按这项直接授权进行有限的原生 UI 测试。未把附件本身当作修改系统的授权。

## 环境与测试前备份

- macOS **26.6.2 / build 25G83**，arm64，Mac17,3。
- 1 块内置显示器，逻辑尺寸 1470×956 点，backing scale 为 2；对应渲染尺寸 2940×1912，不将其当作原生面板物理分辨率。没有本轮外屏测试。
- Space 数量未通过公开只读 API 确认；“在所有空间中显示”原本开启，但不据此宣称已验证多个 Space。
- 原桌面选择为“迪拜天际线”目标 UUID `00BA71CD-2C54-415A-A68A-8358E677D750`，其文件已经是用户先前安装的自定义星空人物视频 A，不把它误记为 Apple 原件。
- 原屏保为“自动”，显示同一 A；启动屏保为 20 分钟后。测试没有调整计时、密码、电源或时钟外观。

在任何壁纸选择变化前，保存完整二进制 `Index.plist`、本机桌面 URL/选项及目标视频 A 副本。配置副本经字节比对，视频副本经 SHA-256 比对。快照目录为 0700，文件为 0600，均位于本机应用支持目录，不提交到公共仓库。

## PoC-A：原生 UI 与真人锁屏观察

通过系统设置操作，不调用私有 Store 写入、桌面覆盖窗口、后台服务或 WallpaperAgent 重载。B 选择系统设置中已存在、明显不同的蓝发人物静态照片，显示方式为“充满屏幕”。

| 顺序 | 操作或证据 | 结果与来源 |
| --- | --- | --- |
| 1 | 原 A → 屏保“自定义”，然后桌面选择 B | 打开屏保设置时发现变回“自动”；说明操作顺序不能被假定为等价。原生 UI 观察 |
| 2 | 先保留桌面 B，再明确选择“自定义”与原 A，并完成 | 桌面设置显示 B，屏保设置显示 A。原生 UI 观察，仅证明选择状态 |
| 3 | 用户按 Control＋Command＋Q，观察约 10 秒后自行解锁 | 用户答复：“锁屏显示 B 或不播放 A，桌面是 B”。该答复未区分 B 与静止 A，但足以说明本轮未通过要求的持续动态 A |
| 4 | 保留 B，将屏保换为已下载的 Apple“太浩湖白天”视频 | 原生 UI 显示该屏保选择，桌面仍显示 B；未重新编码或替换任何视频文件 |
| 5 | 用户再次按 Control＋Command＋Q，观察后自行解锁 | 用户答复：“锁屏界面和桌面都显示 B。”Apple 视频对照同样失败 |
| 6 | 恢复原桌面 A、屏保“自动”与原有全空间开关 | 原生 UI 确认恢复；后续只读快照核对见下文 |

真实锁屏结果来自用户现场观察，不来自自动截图或 plist 键名推断。用户未分别提供每次解锁即刻与 5 秒的逐项结果，不将这些独立检查记为通过。

自然等待屏保、Apple 菜单锁屏、退出应用后的持久性、睡眠唤醒、重启登录、至少 5 次成功循环、电池/外接电源、外屏和多 Space 矩阵均未完成。前置实际锁屏已失败，未继续进行会打断用户的重启或长时间等待测试。没有声称“意外锁屏已修复”。

## PoC-B：只读配置差分与恢复核对

保存基线、原生分离选择、Apple 视频对照及恢复后的本地快照。系统自己生成的基线包含两处 `Type=linked` 与 `Linked`；原生独立选择后包含两处 `Type=individual`、两处 `Desktop` 和两处 `Idle`。Provider/Configuration 计数从 2 增至 4。

**这些结构差异不能证明 Idle 对应真实锁屏。** 实际锁屏观察反而说明该选择路径不满足目标。本轮没有把结构加入写入白名单，没有将这些真实私有快照上传为公共测试夹具。

恢复后核对：

- 目标视频 SHA-256 与测试前一致，未覆盖视频文件。
- 公开 API 返回的桌面 URL 指纹、桌面选项与基线一致。
- 系统设置显示原 A、自动屏保、全空间开启；屏保计时仍为 20 分钟。
- `Index.plist` 原始 SHA 不相同；递归比较仅忽略 `LastSet` / `LastUse` 后完整结构和值相同。系统原生设置更新了使用时间，不声称逐字节恢复。

没有直接覆盖 Store 恢复，不改写未知键、不重载服务、不恢复无关系统设置。原始备份继续保留。PoC-B 中 API 设置 B、单次服务重启与重启后的差分未执行：PoC-A 不通过，尚无理由扩展写入试验。

本机 Store 目录只存在 `Index.plist`，不存在 `Index2.plist`。其他实现提及第二份 Store，因此不能把单一 Index 当作所有系统的完整配置；后续工具也检查第二份文件的可用性。

## 参考证据与解释边界

- [Apple 桌面图片 API](https://developer.apple.com/documentation/appkit/nsworkspace/setdesktopimageurl%28_%3Afor%3Aoptions%3A%29)描述为给指定屏幕设置桌面图片；它本身不是独立锁屏视频设置接口。
- [Apple Tahoe 26 屏保设置](https://support.apple.com/en-ph/guide/mac-help/mchlp1227/26/mac/26)介绍 Automatic / Custom 屏保选择，没有承诺独立真实锁屏 A 与桌面 B。
- [Apple Tahoe 26 墙纸设置](https://support.apple.com/en-gb/guide/mac-help/mchlp1103/26/mac/26)介绍桌面、屏保及全空间选择。这些文档说明与实际锁屏验收分开记录。
- [LiveWallpaper 的 WallpaperStorePatcher 源码](https://github.com/Narcissus-tazetta/LiveWallpaper/blob/main/Sources/LiveWallpaper/Core/Services/LockScreenSyncService%2BWallpaperStorePatcher.swift)将 `Type` 设为 `linked` 并删除 `Idle` / `Desktop`，是联动而非本任务要求的分离，不能照搬。
- [wallall](https://github.com/TresChar/wallall)是第三方私有 Store 桌面写入参考，不是 Apple 的锁屏支持承诺；[Jamf 社区讨论](https://community.jamf.com/general-discussions-2/custom-screensavers-in-sonoma-31256)亦不是当前系统真机通过证据。

本轮结论为“已测原生路径失败，安全自动后端未验证”，不扩大为系统级不可能证明。只有新增可复现且不依赖常驻/覆盖窗口的真实锁屏 A＋桌面 B 证据，才可重新打开 P0，随后进入 P1—P4。

独立 reviewer 的有限扩展调查另发现 [Muro 的 AppleWallpaperStore](https://github.com/MrRockySL/Muro/blob/0414431f86a75932c2010dd35bdfd32c626b7420/Muro/Sources/MuroKit/AppleWallpaperStore.swift) 与 [DesktopStill](https://github.com/MrRockySL/Muro/blob/0414431f86a75932c2010dd35bdfd32c626b7420/Muro/Sources/MuroWallpaperExtension/DesktopStill.swift)。该项目使用私有 WallpaperExtensionKit、系统承载的自定义提供者及会话状态判断来区分静态/动态渲染，不是现有 Apple Aerial 替换加桌面 API。它是未验证的另一种架构研究线索，不是本项目已通过的分离后端；没有下载运行该扩展、注册提供者或修改 Store。

## 只读快照工具

`Scripts/poc_separation_snapshot.swift` 是开发阶段工具，不是应用分离功能。只读取当前用户的 Store、目标视频和公开桌面状态；仅写新建的快照输出目录，拒绝覆盖。缺失、损坏或读取竞态标记不可用。未知键以哈希键名保留递归脱敏子树；不依据键名判定锁屏选择。比较报告只摘要结构变化及已知键计数，详细差异可比较两份脱敏树。

```bash
swiftc -parse-as-library Scripts/poc_separation_snapshot.swift \
  -o /tmp/poc-separation-snapshot -framework AppKit -framework CryptoKit
/tmp/poc-separation-snapshot --output /tmp/p0-before-unique \
  --target-uuid 00BA71CD-2C54-415A-A68A-8358E677D750
/tmp/poc-separation-snapshot --output /tmp/p0-after-unique \
  --target-uuid 00BA71CD-2C54-415A-A68A-8358E677D750 \
  --compare /tmp/p0-before-unique/snapshot.json
```

输出目录必须不存在、父目录必须存在。`raw/Index.plist` 与 `private-state.json` 含原始配置/路径，仅供本机核对，禁止公开；脱敏 `snapshot.json` 仍含配置指纹，分享前检查，不把 SHA-256 当作不可反查的匿名化。工具不自动备份视频；写入实验开始前另行保留视频副本并验证 SHA。初始快照采集后审查修正了未知子树与颜色备份等问题，旧快照不作为新旧算法结构哈希可比证据；本轮真实差分与恢复结论以保留的原始字节和字段比较为准。
